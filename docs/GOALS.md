# Goals

## เป้าหมายหลัก
ทำ HUD แบดมินตันแบบเรียลไทม์ **ที่ทุกตัวเลขมาจากการวัดจริง** จากกล้องตัวเดียวบนเครื่องระดับ RTX 3060 และใช้งานได้ต่อเนื่องครบทั้งแมตช์โดยไม่ต้องมีโปรแกรมเมอร์อยู่หน้างาน

## เป้าหมายที่วัดได้

| # | Goal | ตัวชี้วัด | วัดด้วย |
|---|---|---|---|
| G1 | **เรียลไทม์** | 60 fps, latency end-to-end p50 ≤150ms, p99 ≤250ms | `tools/benchmark.py` |
| G2 | **เสถียร** | เล่นคลิปวน 3 ชม. ไม่ล่ม, RAM และ VRAM ไม่โตขึ้นเกิน 5%, กล้องหลุดแล้วต่อกลับเองได้ภายใน 5 วินาที | `tools/soak_test.py` |
| G3 | **ถ้าส่วนไหนเสียให้ลดฟีเจอร์แทนการล่ม** | ถ้า worker ตัวใดตัวหนึ่งตาย HUD ยังแสดงข้อมูลส่วนอื่นได้ และ restart เองภายใน 3 วินาที | ทดสอบด้วยการ kill worker |
| G4 | **ตัวเลขเป็นของจริง** | ไม่มีตัวเลขสมมติบนหน้าจอ ค่าประมาณต้องติดป้าย "est." | review |
| G5 | **โมเดลเปลี่ยนได้** | เปลี่ยนโมเดลได้ด้วยการแก้ config อย่างเดียว ไม่ต้องแก้โค้ด | ลองสลับไฟล์ `.engine` |
| G6 | **ข้อมูลสะสมเป็น dataset เอง** | ทุก session อัดวิดีโอดิบพร้อมไฟล์ `events.jsonl` ไว้ | ตรวจโฟลเดอร์ `recordings/` |
| G7 | **คนคุมใช้งานง่าย** | คาลิเบรตคอร์ทเสร็จใน ≤60 วินาที และแก้คะแนนหรือสลับ ID ได้จากหน้าเว็บ | ให้คนที่ไม่ใช่ dev ลองใช้ |

## ความแม่น (วัดทีหลังเมื่อมี test set)
- ตำแหน่งบน court map คลาดเคลื่อน <30 cm
- ตรวจเจอลูก >85%
- นับ shot ถูก >90%
- แบ่ง rally ถูก >95%

ช่วงนี้ยังไม่ต้องวัดความแม่น ให้ใช้โมเดลที่เทรนเสร็จแล้วไปก่อน

## Non-goals (ยังไม่ทำ)
- ประเภทคู่
- ตัดสินลูกตกในหรือออกอัตโนมัติ (ระบบแค่แนะนำ ให้คนกดยืนยันเอง)
- ใช้หลายกล้องเพื่อคำนวณตำแหน่ง 3D
- ประมวลผลบนมือถือ (มือถือใช้เป็นกล้องอย่างเดียว)
- ใช้เครื่องที่มี A6000
- ค่า "พลังกาย" ที่ไม่ได้วัดจากเซนเซอร์จริง
