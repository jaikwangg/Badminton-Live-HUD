## Stage 2: doubles-v2

คลิป 1:57 นาที มือถือแนวตั้ง 540×960 วางหลังคอร์ท กล้องขยับเล็กน้อย ประเภทคู่ · commit `be0e510`

**เพิ่มจาก stage 1**
- คาลิเบรตเฟรมแรกอัตโนมัติจากเส้นคอร์ท (ไม่ต้องคลิกมุม)
- หาคอร์ททุกเฟรม และชดเชยการขยับกล้องจากเพดานและผนัง
- ตามลูกจากจุดสว่างที่เคลื่อนที่ โดยไม่มีโมเดลตามลูก
- ช็อตจากลูกกลับทิศที่ไม้ + เสียง โดยบังคับให้สลับฝั่ง
- ความเร็วออกไม้ (ค่าประมาณ) จากสูตรแรงต้านอากาศ
- รายงานตรวจอัตโนมัติ และไฟล์ `config.json` สำหรับแก้ผลเอง
- HUD 1080×1920 สองแบบ: v2 แผงซ้อนในวิดีโอ, v3 แบบ stat UI (ตัวล่าสุด)

**ผล**

| ผู้เล่น | ฝั่ง | ตามได้ | ระยะวิ่ง | ความเร็วสูงสุด |
|---|---|---|---|---|
| บอส | ใกล้ | 94% | 71.4 ม. | 3.8 ม./วิ |
| เทมป์ | ใกล้ | 84% | 75.9 ม. | 3.8 ม./วิ |
| เป้ | ไกล | 81% | 78.6 ม. | 5.5 ม./วิ |
| ตี๋ | ไกล | 76% | 50.0 ม. | 3.7 ม./วิ |

ฝั่งไกล 1 พิกเซลราว 8 ซม. ค่าจึงแกว่งกว่าฝั่งใกล้ ความเร็วสูงสุดของเป้อาจสูงเกินจริง และระยะของตี๋น่าจะต่ำกว่าจริงเพราะช่วงที่ถูกบังไม่นับ

- เส้นคอร์ทที่คำนวณทับเส้นขาวจริง: ค่ากลาง 94% และ 90% ของเฟรมทับไม่ต่ำกว่า 86%
- 8 แรลลี่, 45 ช็อต
  - **19 ช็อตจากระบบอัตโนมัติ** (แรลลี่ 1, 2, 3, 5) ตรวจด้วยตาแล้ว เหลือจุดไม่แน่ใจ 2 จุด (ดู LESSONS)
  - **26 ช็อตใส่เองใน `config.json`** (แรลลี่ 4, 6, 7, 8) เพราะระบบตามลูกฝั่งไกลไม่ได้
- ตรวจตัวตนแบบสุ่ม 14 จุด ถูกทั้งหมด

**ผ่านอะไรแล้ว และยังไม่ผ่านอะไร**
- ทุกการ์ดผ่าน `pytest` และ `ruff` ด้วยข้อมูลปลอม (message ปลอม, เฟรมสังเคราะห์)
- **ยังไม่เคยรันทั้งระบบกับคลิปจริงหรือกล้องจริง** และยังไม่มีตัวเลข fps หรือ latency จาก GPU (PR ที่แตะ hot path เขียนไว้ว่า "needs GPU benchmark")
- ความเร็วลูกเปลี่ยนเป็นสูตรแรงต้านอากาศแล้ว (#28, ดู T08) แต่ยังไม่ได้เทียบกับคลิป

**ตัดสินแล้ว**
- ประเภทคู่อยู่ใน scope: #11 (goals), #10 (contract), #12 (กติกาและการ์ด), #17 (จุดเริ่มพิกัดคอร์ทคือมุมใกล้ซ้ายเมื่อมองจากกล้อง)
- Linux: reader ห้ามลบ shared memory ของ frame ring ตอนออก (#31) ไม่งั้น restart worker ตัวเดียวแล้ว bus ตายทั้งระบบ ทดสอบใน Docker แล้ว

**ยังค้าง**
1. T11: benchmark บน GPU และ soak test
2. ตรวจความแม่นกับคลิปจริง: ID สลับ (เป้าใน GOALS: ไม่เกิน 2 ครั้งต่อนาที) และจำนวนช็อตเทียบกับ 45 ช็อตของ stage 2
3. G7: ให้คนที่ไม่ใช่ dev ลองคาลิเบรต แล้วจับเวลา (เป้า ≤60 วิ)
4. หน้า operator ที่ต่อเข้ามาหลังส่ง `point_suggested` ไปแล้วจะไม่เห็นคำแนะนำนั้น ต้องตัดสินเรื่อง contract ก่อน (เช่น เพิ่มฟิลด์ pending suggestions)
5. ความหมายของการ reset rally (ตอนไหน reset, reset อะไรบ้าง) ยังไม่ได้ตกลง
