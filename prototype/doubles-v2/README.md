# Prototype doubles-v2: HUD จากคลิปมือถือแนวตั้ง (ประเภทคู่)

คลิปจริง 1:57 นาที กล้องมือถือแนวตั้ง 540×960 วางหลังคอร์ท ประมวลผลหลังถ่ายบน CPU แล้วเรนเดอร์วิดีโอ HUD 1080×1920 พร้อมเสียงเดิม

> เป็น prototype พิสูจน์แนวคิด ไม่ได้ทำตาม `docs/CONTRACTS.md` และโครง `src/hud/`

| ผู้เล่น | ฝั่ง | จุดสังเกต |
|---|---|---|
| บอส | ใกล้กล้อง | เสื้อดำแขนกุด |
| เทมป์ | ใกล้กล้อง | เสื้อลาย |
| เป้ | ฝั่งตรงข้าม | เสื้อเขียวเข้ม |
| ตี๋ | ฝั่งตรงข้าม | เสื้อดำ |

ผลลัพธ์: 8 แรลลี่ 45 ช็อต (ดูรายละเอียดทีละช็อตใน `check/report.md`)

## ขั้นตอน (`pipeline/`)

| # | ไฟล์ | ทำอะไร | ผลลัพธ์ |
|---|---|---|---|
| 1 | `audio_onsets.py` | หาเสียงตีลูกจาก onset ช่วง 2–8 kHz | `onsets.json` |
| 2 | `camera.py` | homography ระหว่างเฟรมจากจุดบนเพดานและผนัง (ชดเชยการขยับกล้อง) | `cam.npy` |
| 3 | `detect.py` | YOLO11m + ByteTrack ทุกเฟรม ครอปเฉพาะส่วนคอร์ทแล้วรันที่ imgsz 832 (ความละเอียดต่อพิกเซลเท่ากับภาพเต็มที่ 1280) | `dets.jsonl` |
| 4 | `courtlib.calibrate_first` | คาลิเบรตคอร์ทจากเฟรมแรก: Hough → จุดลู่ของเส้นแนวยาว → เส้นหลัง (0 ม.) กับเส้นเสิร์ฟยาว (0.76 ม.) → จับคู่เส้นแนวยาวด้วย cross-ratio → homography | `Hc0.npy` |
| 5 | `court_track.py` | หาคอร์ททุกเฟรม: เริ่มจากค่าทำนายตามการขยับกล้อง ดึงเข้าหาเส้นขาวจริงครึ่งคอร์ทใกล้ และคาลิเบรตใหม่ทุก 2 เฟรม เลือกผลที่เส้นทับสีขาวมากกว่า | `court.npy` |
| 6 | `chest2.py` → `players.py` | ใครเป็นใคร: ใช้สีเสื้อช่วงอก (ตัดสีพื้นคอร์ทออก) + ฝั่งคอร์ท + ตำแหน่งเดิม แล้วคำนวณความเร็ว ระยะวิ่ง และพลังกาย | `players.json` |
| 7 | `shuttle_cands.py` → `shuttle_track.py` | หาลูก: จุดสว่างเล็กที่สว่างกว่าเฟรม ±3 และ ±10 (ชดเชยกล้องทั้งระนาบพื้นหลังและพื้นคอร์ท) → ต่อเป็นเส้นทาง → เลือกเส้นทางที่เปลี่ยนทิศได้เฉพาะตรงไม้ของผู้เล่น 4 คน | `cands.json`, `shuttle.json` |
| 8 | `shots.py` | ช็อต (ลูกกลับทิศหรือหักทิศที่ไม้ + เสียงตี) ช็อตต้องสลับฝั่ง ความเร็วออกไม้ = (e^(kD) − 1)/(kT) | `events.json` |
| 9 | `render_v3.py` | HUD 1080×1920 แบบ stat UI (ส่วน `render.py` เป็นแบบแผงซ้อนในวิดีโอ) | mp4 |
| 10 | `report.py`, `check_court.py` | รายงานตรวจ: เส้นคอร์ท 8 เฟรม, ภาพทุกช็อต, คำเตือนความเร็วและช่วงห่างของช็อต | `check/` |

`tools/` เป็นสคริปต์ที่ใช้ตรวจด้วยตาระหว่างทำ เช่น แถบภาพทีละเฟรม และกราฟเวลาของลูก คน และเสียง

## รัน

สคริปต์อ่านและเขียนไฟล์ในโฟลเดอร์ปัจจุบัน ให้รวมทุกอย่างไว้ในโฟลเดอร์ทำงานเดียวกันก่อน

```bash
mkdir work && cd work
cp ../pipeline/*.py ../config.json ../data/* .
bash ../../offline-v0/tools/get_fonts.sh                 # ฟอนต์ไทย -> ./fonts
# ถ้ามีคลิปต้นฉบับ src.mov:
ffmpeg -i src.mov -vf fps=30 -c:v libx264 -crf 12 -an a540.mp4
ffmpeg -i src.mov -vf "fps=30,scale=1080:1920:flags=lanczos" -c:v libx264 -crf 15 -an master1080.mp4
ffmpeg -i src.mov -vn -ac 1 -ar 44100 audio.wav
# ข้อมูลใน data/ ครบถึงขั้น 7 แล้ว เริ่มจากขั้น 8 ได้เลย:
python3 shots.py && python3 report.py && python3 render_v3.py out.mp4    # report/render ต้องมีวิดีโอ
```

## แก้ผลด้วย `config.json`

- `add_shots`: เพิ่มช็อต `{"t": 12.34, "player": "บอส"}` จะแทนที่ช็อตอัตโนมัติที่อยู่ห่างไม่เกิน 0.25 วิ
- `remove_shots`: ลบช็อตตามเวลา
- `rally_end`: กำหนดเวลาจบแรลลี่ `{"<เวลาใดก็ได้ในแรลลี่>": เวลาจบ}`
- `ignore_ranges`: ช่วงที่ไม่ใช่แรลลี่ เช่น ส่งลูกเล่นระหว่างแต้ม

**ข้อมูลใน config ตอนนี้:** แรลลี่ 4, 6, 7 และ 8 เกือบทั้งหมดผมใส่เองหลังไล่ดูภาพทีละเฟรม เพราะระบบตามลูกฝั่งตรงข้ามไม่ได้ ลูกเล็กมากและไปซ้อนกับคนนั่งข้างสนาม

## ภาพตรวจและวิดีโอ

- ภาพตรวจอยู่ใน `check/`: เส้นคอร์ท 8 เฟรม (`court_8frames.jpg`), ภาพทุกช็อต (`shots_rally*.jpg`), preview HUD (`check/hud/`)
- คลิปต้นฉบับ, `a540.mp4`, `master1080.mp4`, `audio.wav` และวิดีโอผลลัพธ์อยู่ใน branch [`media`](https://github.com/jaikwangg/Badminton-Live-HUD/tree/media/stage2-doubles-v2) ก๊อปมาไว้ในโฟลเดอร์ `work/` แล้วรันขั้น 8 ต่อได้เลยโดยไม่ต้องแปลงคลิปใหม่
- ไม่มีไฟล์โมเดล `*.pt` ใน repo จะถูกโหลดอัตโนมัติตอนรันครั้งแรก

ความคืบหน้าและบทเรียนของ prototype นี้: `docs/PROGRESS.md`, `docs/LESSONS.md`

## ข้อจำกัดที่รู้แล้ว

- **ความเร็วลูก:**
  - ช็อตที่ห่างกัน ~0.3 วิ ได้ตัวเลขสูงเกินจริง เช่น 325 km/h
  - ลูกโด่งได้ตัวเลขต่ำเกินจริง เพราะสูตรคิดแค่ระยะบนพื้น
- **พลังกาย:** เป็นค่าที่คำนวณจากความเร็วและระยะวิ่ง ไม่ได้วัดจากร่างกาย
- **ฝั่งตรงข้าม:** 1 พิกเซลเท่ากับราว 8 ซม. ตำแหน่งจึงแกว่ง และช่วงที่ถูกบังจะไม่นับระยะ
